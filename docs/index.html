§ 1 · LLM Wiki란?

왜 위키를 만드는가

"RAG는 매번 검색해서 답을 만든다. LLM Wiki는 지식이 쌓여서 답이 더 좋아진다." — Andrej Karpathy, 2026.

옵시디언 마크다운 폴더 + AI 스킬 한 개만 있으면 시작 가능. 데이터베이스·서버 X.

13계층 구조 (Karpathy 표준)

raw    — 불변 원자료 (웹 클리핑, 대화 기록, 메모)
wiki   — AI가 만든 마크다운 (요약 · 엔티티 · 상호 링크)
schema — 운영 규칙 (CLAUDE.md, lint 정책)

23가지 핵심 작업

  • ingest — 새 raw → wiki 페이지 생성
  • query — 위키만 읽고 답변 합성
  • lint — 끊긴 링크 · 중복 정리

이 3가지가 LLM Wiki의 최소 단위. 모든 도구·플러그인이 같은 패턴.

§ 2 · 옵시디언 웹 클리퍼

웹 클리퍼로 raw 수집

왜? raw 폴더가 없으면 ingest할 자료가 없습니다. 첫 단계는 자료를 모으는 입구를 만드는 것.

옵시디언 공식 Chrome/Firefox 확장. 웹 페이지를 깔끔한 마크다운으로 옵시디언 볼트에 직접 저장. 무료, 1분 설치.

1설치

  1. 옵시디언 앱이 없으면 먼저 obsidian.md에서 설치
  2. obsidian.md/clipper에서 브라우저 확장 설치 (Chrome · Firefox · Edge)
  3. 옵시디언 앱에서 raw 폴더 지정 (예: raw/articles/)
  4. 템플릿 선택 — 기본 "Default"면 충분

2사용

  1. 저장하고 싶은 웹 페이지에서 확장 아이콘 클릭
  2. 제목·태그·요약 자동 추출 → 볼트에 .md 파일 생성
  3. raw 폴더에 즉시 반영
raw는 절대 수정 X — 원본 그대로 보존. 가공·요약·엔티티 추출은 다음 단계 wiki 스킬의 ingest에서 자동.
§ 3 · wiki 스킬

wiki 스킬로 raw → wiki 변환

왜? raw만 쌓아두면 쓰레기통. 요약·엔티티·링크를 만들어야 검색·활용 가능한 자산이 됩니다.

오픈소스 wiki 스킬은 9개 표준 operation을 제공합니다. Claude Code · Codex · Antigravity 어디서나 동일한 자연어로 호출.

영상 · 60초 raw → wiki ingest 흐름 — 원본 5개 → AI 컴파일 → 페이지·엔티티 그래프

2자연어 호출 — 이름 외울 필요 X

상황을 말하면 AI가 적합한 operation을 자동 선택. 처음엔 ingest · query 2개만으로 충분.

이런 상황에서이렇게 말하면실행되는 operation
새 raw 처리하고 싶을 때"오늘 클리퍼로 모은 글 5개 ingest"ingest

§ 4 · 환경별 설치

각 환경 폴더로 cd → git clone

왜? 마켓플레이스 자연어 설치는 도구 의존적. git clone은 어디서나 동일하게 작동합니다.

각 도구마다 고유 스킬 폴더가 있습니다. 그 폴더로 이동 → git clone 한 줄. 끝.

1방법 A — git clone (모든 환경 표준 · 추천)

Claude Code
~/.claude/skills/ 
mkdir -p ~/.claude/skills
cd ~/.claude/skills
git clone https://github.com/<owner>/<wiki-skill-repo> wiki

# 검증
ls ~/.claude/skills/wiki/SKILL.md
Codex CLI (OpenAI)
~/.copilot/skills/ 
# Windows 네이티브 설치
winget install --id OpenAI.Codex -e
codex --version

mkdir -p ~/.copilot/skills
cd ~/.copilot/skills
git clone https://github.com/<owner>/<wiki-skill-repo> wiki
Google Antigravity
.github/skills/ (프로젝트별) 
# Antigravity 설치
# https://codelabs.developers.google.com/getting-started-google-antigravity

cd /path/to/your-project
mkdir -p .github/skills
cd .github/skills
git clone https://github.com/<owner>/<wiki-skill-repo> wiki

방법 A(git clone) 추천 이유
• 표준 — 모든 OS·도구·환경에서 동일 명령
• 버전 관리 — git pull로 업데이트
• 오프라인 OK — 회사망 마켓 접근 제한되어도 git만 되면 동작
§ 5 · QMD 검색 (선택)

QMD — 사내 마크다운 1초 검색

왜? 위키 페이지가 100개 넘어가면 키워드 검색만으로 부족. 의미 검색으로 "관련 페이지" 즉시 회상.

영상 · 60초 QMD — 4기능 (의미·키워드 검색 / 로컬 임베딩 / 점수 게이트 / 1초 응답)

옵시디언 볼트 전체를 로컬 임베딩으로 인덱싱하는 CLI 도구. 외부 API 호출 0, 토큰비 0.

1설치 (Python pip)

pip install qmd-cli
qmd --version

2볼트 등록 (1회만)

qmd init /path/to/your-vault
qmd config set embed_model bge-m3
qmd update && qmd embed

3활용 명령

명령역할
qmd search "쿼리"키워드 검색 (BM25)
qmd query "쿼리"의미 검색 (벡터)
qmd update새 파일 인덱싱
qmd embed임베딩 재계산
임베딩은 자동 X — qmd update를 직접 호출해야 인덱스 갱신. 매일 한 번씩 수동 호출이 가장 단순. 자주 갱신하고 싶으면 §8 cron으로 자동화.
§ 6 · 옵시디언 보조 플러그인 (선택)

옵시디언 GUI에서 즉시 활용

왜? AI 스킬 외에 옵시디언 자체에도 위키 운영 도구가 풍부. GUI에서 바로 검색·시각화·자동 채우기.

플러그인역할활용 포인트
Web Clipper (공식) 웹 → 마크다운 raw raw 수집 입구 (§2)
Smart Connections 로컬 임베딩 의미 검색 옵시디언 GUI에서 즉시 query (QMD CLI 대신)
Dataview 마크다운 쿼리 "최근 ingest된 페이지 5개" 동적 테이블
Templater 템플릿 자동 채우기 raw → wiki 변환 시 frontmatter 자동 생성
Copilot for Obsidian 옵시디언 안 AI 채팅 볼트 컨텍스트로 질의 (API 키 필요)
Text Generator 템플릿 기반 AI 생성 요약·태그 자동 생성
Excalidraw 다이어그램 · 화이트보드 엔티티 관계도 시각화
역할 분담 — 옵시디언 플러그인은 GUI에서 즉시 활용. AI 스킬(wiki / QMD)은 CLI·AI 도구에서 호출. 둘은 같은 raw 폴더를 공유.
§ 7 · agentmemory (선택 · 별도 트랙)

AI 세션을 자동 메모리로

왜? wiki는 외부 자료 수집·컴파일. agentmemory는 AI 대화·결정 자체를 4-tier 메모리로 저장. 별도 트랙으로 운영하면 강력.

wiki(외부 raw)와 다른 입력원 — AI 세션 자체. 수동 호출 위주로 시작 → 자동 캡처(hooks)는 익숙해진 후 선택.

1설치

npx @agentmemory/agentmemory

# 자동 등록되는 것:
# - 4-tier 메모리 SQLite (외부 의존성 0)
# - 51 MCP tools (memory_recall, memory_save, memory_smart_search 등)
# - 12 hooks (선택 — 기본 비활성, 별도 설정으로 활성)

24-tier 메모리

Tier의미예시
① Working현재 작업 (raw observations)"방금 X 파일 수정 중"
② Episodic세션 일화 (compressed summaries)"어제 인증 모듈 작업"
③ Semantic의미적 사실·패턴"우리 팀은 JWT 사용"
④ Procedural워크플로우·결정 패턴"디버깅 4단계 절차"

3수동 호출 (권장 — 처음엔 이것만)

# 자연어로 호출 — MCP tool이 자동 활성화
"이전에 OAuth 관련 작업 메모리에서 찾아줘"
  → memory_smart_search 자동 호출

"오늘 결정 사항 메모리에 저장해줘 — JWT refresh 패턴 채택"
  → memory_save 자동 호출

"지난 주 디버깅 절차 회상해줘"
  → memory_recall + episodic tier 검색
자동 캡처(12 hooks)는 별도 설정 — 기본은 수동만. wiki ingest · 하네스 룰과 겹칠 수 있어 처음엔 수동 호출만으로 충분합니다. 자동 캡처 원하면 ~/.claude/settings.json에서 hooks 활성화 (선택).
wiki와 역할 분담
• wiki 스킬 — 옵시디언 raw → wiki 마크다운 컴파일 (외부 자료)
• agentmemory — AI 세션 결정·실수·맥락 (내부 컨텍스트)
• 두 시스템은 독립 — 겹치지 않게 별도 트랙으로 운영
§ 8 · cron 자동화 (선택 · 고급)

QMD 갱신 · wiki ingest 자동 실행

왜? 매번 수동 호출이 번거로우면 시스템 스케줄러로 자동화. 기본은 수동, 익숙해진 후 추가.

QMD 인덱싱 + raw 폴더 ingest를 시스템 스케줄러로 자동화. 백그라운드에서 위키가 스스로 자랍니다.

1QMD 30분 주기 인덱싱

Windows · Task Scheduler
schtasks (관리자 PowerShell) 
schtasks /create /tn "QMD Update" ^
  /tr "wsl bash -c 'qmd update && qmd embed'" ^
  /sc MINUTE /mo 30 /ru "%USERNAME%"

# 확인
schtasks /query /tn "QMD Update"

# 삭제 (필요시)
schtasks /delete /tn "QMD Update" /f

또는 GUI: 작업 스케줄러 → 작업 만들기 → 트리거 "30분마다 반복" → 동작 "wsl bash -c '...'"

Mac · cron
crontab -e 
# crontab -e 편집 후 한 줄 추가
*/30 * * * * /usr/local/bin/qmd update && /usr/local/bin/qmd embed

# 확인
crontab -l

2매일 아침 9시 — raw → wiki ingest

Windows · Task Scheduler
매일 09:00 
# Claude Code 환경
schtasks /create /tn "Wiki Ingest Morning" ^
  /tr "wsl bash -c 'claude --print \"raw 폴더 새 파일 ingest해줘\"'" ^
  /sc DAILY /st 09:00 /ru "%USERNAME%"
Mac · cron
매일 09:00 
0 9 * * * /usr/local/bin/claude --print "raw 폴더 새 파일 ingest해줘"

3cron 주기 표 (참고)

cron 표현의미용도
*/30 * * * *30분마다QMD 인덱싱
0 * * * *매시 정각가벼운 갱신

0 9 * * 1-5평일 9시출근일만
처음엔 수동으로 충분 — 매일 아침 직접 "ingest해줘" 한 번 호출이 가장 단순. cron은 익숙해진 후 추가하세요. 자동화해도 위키 결과는 반드시 검토 필요 (AI가 잘못 합성할 수 있음).
