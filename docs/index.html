§ 1 · LLM Wiki 패턴

왜 위키인가

"RAG는 매번 검색해서 답을 만든다. LLM Wiki는 지식이 쌓여서 답이 더 좋아진다." — Andrej Karpathy.

13계층 구조

raw    — 불변 원자료 (대화 기록, 프로젝트 메모, 웹 클리핑)
wiki   — AI 소유 마크다운 (요약 · 엔티티 · 상호 링크)
schema — 운영 규칙 (CLAUDE.md, lint 정책)

§ 2 · 옵시디언 웹 클리퍼

웹 클리퍼로 raw 수집

옵시디언 공식 Chrome/Firefox 확장. 웹 페이지를 깔끔한 마크다운으로 옵시디언 볼트에 직접 저장.

1설치 (1분)

  1. obsidian.md/clipper에서 브라우저 확장 설치
  2. 옵시디언 앱에서 볼트 폴더 지정 (예: 10_Raw/01_Articles/)
  3. 템플릿 선택 — 기본 "Default" 또는 커스텀 (frontmatter + 본문)

2사용

  1. 저장하고 싶은 웹 페이지에서 확장 아이콘 클릭
  2. 제목·태그·요약 자동 추출 → 볼트에 .md 파일 생성
  3. raw 폴더에 즉시 반영 (불변)
raw는 절대 수정 X — 원본 그대로 보존. 가공·요약·엔티티 추출은 모두 다음 단계 /wiki ingest에서.
§ 3 · /wiki ingest 흐름

raw → wiki 변환

클리퍼로 수집한 raw 파일을 AI가 읽고, 요약·엔티티·상호 링크를 만들어 20_Wiki/에 저장. 단순 복사가 아닌 지식 컴파일.

1자연어 호출

"오늘 클리퍼로 모은 raw 5개를 ingest해줘."

# /wiki 스킬 자동 활성화
# → refs/ingest.md lazy load
# → Gold In 5필드 자동 추출
# → 20_Wiki/ 페이지 생성
# → 기존 엔티티와 자동 링크

2Gold In 5필드 (Soft 필터)

raw가 "쓰레기통"이 되지 않도록, ingest 시 5개 필드를 자동 추출·확인:

필드의미
1. 수집 이유왜 모았나? (목적)
2. My Take내 관점에서 의의?
3. 한 줄 통찰핵심 한 문장
4. Gold Out그래서 뭘 얻었나? (수집 이유 비대칭 검증)
5. Action Intent{action}: {target} 예: "synthesize: harness §1"

"왜 수집했는지 + 뭘 얻었는지 + 어디 쓸지" 답 못하면 Garbage In — Karpathy 철학 물리적 강제.

34-Tier 검색 (ingest 후 query 시)

Tier 1 — 20_Wiki (컴파일 지식, 자동 first)
Tier 2 — 30_Claude (협업 기록, 자동)
Tier 3 — 10_Raw (원본, 수동만 — "원본" 명시 시)
Tier 4 — 외부 (Brave + Firecrawl, 마지막 폴백)

§ 5 · 자연어 호출 데모

스킬 이름 외울 필요 X

상황을 그대로 말하면 AI가 적합한 verb를 자동 활성화. 9개 동사를 외울 필요 없습니다.

상황자연어 호출발동 verb
새 raw 처리"오늘 클리퍼로 모은 글 5개 정리해줘"ingest
지식 회상"이전에 OO 관련 작업 있었나?"query
세션 마무리"오늘 작업 위키에 저장해줘"save
구조 검증"끊긴 링크 · 중복 페이지 정리"lint
여러 자료 합성"이 5개 페이지로 종합 페이지 만들어줘"synthesize
모순 점검"이 결정 다른 페이지와 충돌 없나?"critique
두 개념 비교"A와 B 차이 5차원으로"compare
쉽게 설명"이거 초등학생도 알 수 있게"eli5
§ 6 · agentmemory 통합

자동 캡처 — 수동 ingest 보완

옵시디언 클리퍼 = 수동 raw 수집. agentmemory = AI 세션 자체를 자동 캡처. 두 입력원이 wiki를 살찌움.

1설치

npx @agentmemory/agentmemory

# - 51 MCP tools (memory_recall, memory_save 등)

24-tier 메모리

Tier의미
① Working현재 작업 (raw observations)
② Episodic세션 일화 (compressed summaries)
③ Semantic의미적 사실 · 패턴

§ 7 · QMD 설치 + 활용

QMD — 사내 마크다운 1초 검색

영상 · 60초 QMD — 4기능 (의미·키워드 검색 / 로컬 임베딩 / 점수 게이트 / 1초 응답)

옵시디언 볼트 전체를 로컬 임베딩으로 인덱싱. /wiki query의 Tier 1·2 검색 엔진 역할.

1설치

# Python pip (가장 빠름)
pip install qmd-cli

# 또는 git clone (개발자)
git clone https://github.com/danielmiessler/qmd ~/.local/qmd
cd ~/.local/qmd && pip install -e .

# 검증
qmd --version

2볼트 등록 (1회)

# 옵시디언 볼트 경로 지정
qmd init /path/to/Zettelkasten

# 임베딩 모델 (다국어 — 한국어·영어 동시 처리)
qmd config set embed_model bge-m3

# 최초 인덱싱 (수백 파일 약 1~3분)
qmd update && qmd embed

3활용 명령

명령역할
qmd search "쿼리"BM25 키워드 검색 (빠름)
qmd query "쿼리"의미 벡터 검색 (RRF)
qmd update새/변경 파일 인덱싱 (증분)
qmd embed임베딩 재계산
qmd status인덱스 상태 확인 (전체 파일 수 · 마지막 업데이트)
qmd reindex전체 재인덱싱 (모델 변경 시)
임베딩은 자동 X — qmd update를 호출해야 변경된 파일이 인덱스에 반영됩니다. 새 raw가 자주 들어오면 §8 크론잡으로 30분 주기 자동 실행 권장.

§ 8 · 자동화 cron

QMD 30분 · wiki 아침 9시 자동 실행

QMD 인덱싱 + raw 폴더 ingest를 시스템 스케줄러로 자동화. 사용자가 매번 명령 호출 X — 백그라운드에서 위키가 스스로 자란다.

1QMD 30분 주기 인덱싱

Windows · Task Scheduler
schtasks (PowerShell 관리자) 
schtasks /create /tn "QMD Update" ^
  /tr "wsl bash -c 'qmd update && qmd embed'" ^
  /sc MINUTE /mo 30 /ru "%USERNAME%"

# 확인
schtasks /query /tn "QMD Update"

# 삭제 (필요시)
schtasks /delete /tn "QMD Update" /f

또는 GUI: 작업 스케줄러 → 작업 만들기 → 트리거 "30분마다 반복" → 동작 "wsl bash -c '...'"

Mac · cron 또는 launchd
crontab -e 
# crontab -e 편집 후 한 줄 추가
*/30 * * * * /usr/local/bin/qmd update && /usr/local/bin/qmd embed

# 확인
crontab -l

# 또는 launchd (~/Library/LaunchAgents/com.qmd.update.plist)
# StartInterval: 1800 (초 단위 = 30분)
# 로드: launchctl load ~/Library/LaunchAgents/com.qmd.update.plist

2매일 아침 9시 — raw → wiki ingest

Windows · Task Scheduler
매일 09:00 
schtasks /create /tn "Wiki Ingest Morning" ^
  /tr "wsl bash -c 'claude --print \"raw 폴더 새 파일 ingest해줘\"'" ^
  /sc DAILY /st 09:00 /ru "%USERNAME%"

# Codex 환경
schtasks /create /tn "Wiki Ingest Codex" ^
  /tr "wsl bash -c 'codex exec \"raw 폴더 ingest\"'" ^
  /sc DAILY /st 09:00
Mac · cron
매일 09:00 
# crontab -e
0 9 * * * /usr/local/bin/claude --print "raw 폴더 새 파일 ingest해줘"

# 로그 남기기
0 9 * * * /usr/local/bin/claude --print "raw 폴더 ingest" >> ~/.qmd/ingest.log 2>&1

3실전 흐름

  1. 낮 동안 옵시디언 클리퍼로 raw 수동 수집 (관심 자료 클립)
  2. 30분마다 QMD가 새 raw 자동 인덱싱 → 검색 즉시 가능
  3. 다음 날 아침 9시 — Claude/Codex가 raw 폴더 자동 ingest → wiki 페이지 생성 + 엔티티 링크
  4. 출근 후 위키만 열어보면 어제 수집 자료가 이미 컴파일 완료된 상태

4cron 주기 표

cron 표현의미용도
*/15 * * * *15분마다매우 활발한 수집
*/30 * * * *30분마다 (권장)일반 사용
0 * * * *매시 정각가벼운 사용
0 9 * * *매일 9시wiki ingest (raw → wiki)
0 9 * * 1-5평일 9시출근일만 ingest
0 9,18 * * *매일 9시 + 18시아침 + 퇴근 전 2회
Gold In 5필드는 수동 확인 — cron으로 ingest 자동화해도, "왜 모았는지" 빈 페이지는 자동 채우기 어렵습니다. 다음 날 아침 위키 검토 시 5필드(수집 이유 / My Take / 한 줄 통찰 / Gold Out / Action Intent) 수동 보강 권장.
