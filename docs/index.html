Karpathy LLM Wiki 패턴 — 옵시디언 웹 클리퍼로 raw 수집 → 표준 wiki 스킬로 ingest → QMD 검색 → 시스템 cron으로 자동화. Claude Code · Codex CLI · Google Antigravity 환경 동일 적용.

영상 · 60초 LLM 위키 — RAG가 아니라 축적
§ 1 · LLM Wiki 패턴

왜 위키인가

"RAG는 매번 검색해서 답을 만든다. LLM Wiki는 지식이 쌓여서 답이 더 좋아진다." — Andrej Karpathy, 2026.

13계층 구조 (Karpathy 표준)

raw    — 불변 원자료 (대화 기록, 프로젝트 메모, 웹 클리핑)
wiki   — AI 소유 마크다운 (요약 · 엔티티 · 상호 링크)
schema — 운영 규칙 (CLAUDE.md, lint 정책)

23가지 핵심 작업

  • ingest — 새 raw → wiki 페이지·엔티티 생성
  • query — 위키만 읽고 답변 합성
  • lint — 끊긴 링크 · 중복 개념 · 낡은 규칙 정리

이 3가지가 LLM Wiki의 최소 단위. 도구·플러그인이 달라도 이 패턴은 동일합니다.

§ 2 · 옵시디언 웹 클리퍼

웹 클리퍼로 raw 수집

옵시디언 공식 Chrome/Firefox 확장. 웹 페이지를 깔끔한 마크다운으로 옵시디언 볼트에 직접 저장. 무료, 1분 설치.

1설치

  1. obsidian.md/clipper에서 브라우저 확장 설치 (Chrome · Firefox · Edge)
  2. 옵시디언 앱에서 raw 폴더 지정 (예: raw/articles/)
  3. 템플릿 선택 — 기본 "Default" 또는 frontmatter 커스텀

2사용

  1. 저장하고 싶은 웹 페이지에서 확장 아이콘 클릭
  2. 제목·태그·요약 자동 추출 → 볼트에 .md 파일 생성
  3. raw 폴더에 즉시 반영 (불변)
raw는 절대 수정 X — 원본 그대로 보존. 가공·요약·엔티티 추출은 다음 단계 wiki 스킬의 ingest에서.
§ 3 · wiki 스킬 (표준)

표준 wiki 스킬로 ingest

오픈소스 wiki 스킬은 9개 표준 operation을 제공합니다. Claude Code/Codex/Antigravity 어디서나 동일한 명령으로 호출.

19개 표준 operation

ingest
raw → wiki 페이지 생성 (여러 페이지 동시 가능)
query
키워드·태그·카테고리 검색 + 결과 합성
lint
고아 페이지 · 끊긴 링크 · stale 콘텐츠 점검
add
간단 페이지 추가 (ingest 가벼운 버전)
list
전체 페이지 목록 (index.md)
read
특정 페이지 읽기
delete
페이지 삭제
log
operation 이력 (log.md)
save
세션 결과 자동 저장 (auto-capture)

2자연어 호출 예시

상황자연어 호출operation
새 raw 처리"오늘 클리퍼로 모은 글 5개 ingest"ingest
지식 회상"이전에 인증 관련 작업 있었나?"query
구조 검증"끊긴 링크 · 중복 페이지 점검"lint
간단 메모"이 결정 위키에 페이지로 추가"add
위키 둘러보기"위키에 어떤 페이지 있나"list
특정 페이지"auth-architecture 페이지 읽어줘"read
세션 마무리"오늘 작업 자동 저장"save

상황을 자연어로 말하면 AI가 적합한 operation을 자동 활성화. operation 이름을 외울 필요 없습니다.

§ 4 · 옵시디언 보조 플러그인

옵시디언 안의 위키 운영 도구

옵시디언 자체에도 위키 운영에 유용한 무료 플러그인이 많습니다. AI 스킬과 별개로 옵시디언 GUI에서 직접 활용.

§ 5 · 환경별 설치

표준 흐름 — git clone + 등록

SKILL.md 형식이 GitHub Agent Skills 표준이라 Claude Code · Codex CLI · Google Antigravity가 같은 스킬 파일을 인식. 가장 깔끔한 방법은 git clone 1번 → 환경별 디렉토리에 심볼릭 링크. 마켓플레이스 자연어 설치는 환경 의존적이라 비추천.

1공통 — 1번만 git clone

# 한 본을 받아서 모든 환경에서 공유
git clone https://github.com/<owner>/<wiki-skill-repo> ~/skills/wiki

# 예시 (anthropics 공식 스킬 모음)
git clone https://github.com/anthropics/skills ~/skills/anthropics

# 한 번 받은 폴더를 환경별로 link만 걸면 끝

2환경별 등록 (심볼릭 링크)

mkdir -p ~/.claude/skills
ln -s ~/skills/wiki ~/.claude/skills/wiki

# 또는 복사 (환경 분리)

# 검증

왜 git clone 방식?
• 표준 — 모든 OS·도구·환경에서 동일 명령. 마켓플레이스 의존 X
• 버전 관리 — git pull로 업데이트, git log로 이력 추적
• 심볼릭 링크 = 한 본 운영 — 한 번 update → 3개 환경 자동 반영
• 오프라인 — 마켓 접근 제한된 회사망에서도 동작
• 커스터마이즈 — 본인 fork 후 수정해도 동일 워크플로우
Windows 심볼릭 링크 — 관리자 PowerShell에서 New-Item -ItemType SymbolicLink -Path ~/.claude/skills/wiki -Target ~/skills/wiki. 또는 WSL에서 ln -s 그대로 사용.
§ 6 · QMD 검색 엔진

QMD — 사내 마크다운 1초 검색

영상 · 60초 QMD — 4기능 (의미·키워드 검색 / 로컬 임베딩 / 점수 게이트 / 1초 응답)

옵시디언 볼트 전체를 로컬 임베딩으로 인덱싱하는 CLI 도구. wiki query의 백엔드 역할 — 외부 API 호출 0, 토큰비 0.

1설치

# Python pip
pip install qmd-cli

# 검증
qmd --version

2볼트 등록 (1회)

# 옵시디언 볼트 경로 지정
qmd init /path/to/your-vault

# 임베딩 모델 (다국어 — 한국어·영어 동시 처리)
qmd config set embed_model bge-m3

# 최초 인덱싱 (수백 파일 약 1~3분)
qmd update && qmd embed

3활용 명령

명령역할
qmd search "쿼리"BM25 키워드 검색 (빠름)
qmd query "쿼리"의미 벡터 검색 (RRF)
qmd update새/변경 파일 인덱싱 (증분)
qmd embed임베딩 재계산
qmd status인덱스 상태 (전체 파일 수 · 마지막 업데이트)
qmd reindex전체 재인덱싱 (모델 변경 시)
임베딩은 자동 X — qmd update를 직접 호출해야 인덱스 갱신. 새 raw가 자주 들어오면 §8 cron으로 30분 주기 자동화 권장.
§ 7 · agentmemory (자동 캡처)

세션 자체를 자동 메모리로

옵시디언 클리퍼 = 수동 외부 수집. agentmemory = AI 세션 자동 캡처. 두 입력원이 위키를 살찌웁니다.

1설치

npx @agentmemory/agentmemory

# 자동 등록:
# - 12 hooks (SessionStart/End, PreToolUse, UserPromptSubmit 등)
# - 51 MCP tools (memory_recall, memory_save 등)
# - 4-tier 메모리 SQLite

24-tier 메모리

Tier의미예시
① Working현재 작업 (raw observations)"방금 X 파일 수정 중"
② Episodic세션 일화 (compressed summaries)"어제 인증 모듈 작업"
③ Semantic의미적 사실·패턴"우리 팀은 JWT 사용"
④ Procedural워크플로우·결정 패턴"디버깅 4단계 절차"

도구역할입력원

§ 8 · 자동화 cron

QMD 30분 · wiki 아침 9시 자동 실행

QMD 인덱싱 + raw 폴더 ingest를 시스템 스케줄러로 자동화. 매번 명령 호출 X — 백그라운드에서 위키가 스스로 자랍니다.

1QMD 30분 주기 인덱싱

Windows · Task Scheduler
schtasks (PowerShell 관리자) 
schtasks /create /tn "QMD Update" ^
  /tr "wsl bash -c 'qmd update && qmd embed'" ^
  /sc MINUTE /mo 30 /ru "%USERNAME%"

# 확인
schtasks /query /tn "QMD Update"

# 삭제 (필요시)
schtasks /delete /tn "QMD Update" /f

또는 GUI: 작업 스케줄러 → 작업 만들기 → 트리거 "30분마다 반복" → 동작 "wsl bash -c '...'"

Mac · cron 또는 launchd
crontab -e 
# crontab -e 편집 후 한 줄 추가
*/30 * * * * /usr/local/bin/qmd update && /usr/local/bin/qmd embed

# 확인
crontab -l

# 또는 launchd (~/Library/LaunchAgents/com.qmd.update.plist)
# StartInterval: 1800 (초 단위 = 30분)
# 로드: launchctl load ~/Library/LaunchAgents/com.qmd.update.plist

2매일 아침 9시 — raw → wiki ingest

Windows · Task Scheduler
매일 09:00 
# Claude Code 환경
schtasks /create /tn "Wiki Ingest Morning" ^
  /tr "wsl bash -c 'claude --print \"raw 폴더 새 파일 ingest해줘\"'" ^
  /sc DAILY /st 09:00 /ru "%USERNAME%"

# Codex CLI 환경
schtasks /create /tn "Wiki Ingest Codex" ^
  /tr "wsl bash -c 'codex exec \"raw 폴더 ingest\"'" ^
  /sc DAILY /st 09:00
Mac · cron
매일 09:00 
# crontab -e
0 9 * * * /usr/local/bin/claude --print "raw 폴더 새 파일 ingest해줘"

# 로그 남기기
0 9 * * * /usr/local/bin/claude --print "raw 폴더 ingest" >> ~/.qmd/ingest.log 2>&1

3실전 흐름

  1. 낮 동안 옵시디언 클리퍼로 raw 수동 수집 (관심 자료 클립)
  2. 30분마다 QMD가 새 raw 자동 인덱싱 → 검색 즉시 가능
  3. 다음 날 아침 9시 — Claude/Codex가 raw 폴더 자동 ingest → wiki 페이지 생성 + 엔티티 링크
  4. 출근 후 위키만 열어보면 어제 수집 자료가 이미 컴파일 완료된 상태

4cron 주기 표

cron 표현의미용도
*/15 * * * *15분마다매우 활발한 수집
*/30 * * * *30분마다 (권장)일반 사용 (QMD)
0 * * * *매시 정각가벼운 사용
0 9 * * *매일 9시wiki ingest (raw → wiki)
0 9 * * 1-5평일 9시출근일만 ingest
0 9,18 * * *매일 9시 + 18시아침 + 퇴근 전 2회
ingest 자동화 한계 — cron으로 ingest 자동 실행해도, "왜 모았는지" 같은 의미 필드는 자동 채우기 어렵습니다. 다음 날 아침 위키 검토 시 수동 보강 권장.
